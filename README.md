# reviewer

[![CI](https://github.com/Aariso0/reviewer/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Aariso0/reviewer/actions/workflows/ci.yml)
[![License: Apache-2.0](https://img.shields.io/badge/License-Apache--2.0-blue.svg)](LICENSE)

Set up an AI pull-request reviewer on GitHub Actions from inside any git repository. `reviewer` writes three files, asks for an API key once, and leaves a workflow that posts one `COMMENT` review per pull request.

## 1. What it does

- Runs `reviewer init` in your repository; it asks for provider, model, base URL, runner label and optional extra rules.
- Reads the API key with hidden input (or from `AI_REVIEW_API_KEY`) and sends it to `gh secret set` on stdin. The key is never placed in arguments, generated files, logs or git.
- Writes only:
  - `.github/reviewer/review.py`
  - `.github/reviewer/prompt.md`
  - `.github/workflows/pr-review.yml`
- The generated workflow checks out only `.github/reviewer`, runs `python3 .github/reviewer/review.py`, and uses `${{ secrets.AI_REVIEW_API_KEY }}` plus `${{ github.token }}`.
- The runner fetches the PR and diff, reviews only valid new-side lines, posts one inline-capable `COMMENT` review, and never fails CI.

## 2. Requirements

- Python 3.8 or newer.
- Git, and a git repository.
- The [GitHub CLI](https://cli.github.com/) (`gh`), logged in with `gh auth login`, to set the repository secret automatically. Without it the wizard prints manual instructions.
- An API key for the chosen provider, except Ollama for a local server.

## 3. Install

```sh
pipx install git+https://github.com/Aariso0/reviewer
```

Or from a checkout:

```sh
pip install .
```

Or run without installing:

```sh
PYTHONPATH=src python3 -m reviewer init
```

After installation, `reviewer` is on your `PATH`; `python -m reviewer` works too.

## 4. Quick start

```sh
cd /path/to/your/repo
reviewer init
```

The wizard covers: provider, model, base URL, runner, extra rules, hidden key, plan, write, secret, optional commit/push, and final manual steps. To see the plan without writing:

```sh
reviewer init --dry-run --yes --no-banner
```

## 5. CLI reference

| Command | Meaning |
| --- | --- |
| `reviewer init` | Interactive setup wizard. |
| `reviewer init --dry-run` | Print the plan; write nothing. |
| `reviewer init --yes` | Accept defaults and overwrite generated files without asking. |
| `reviewer init --no-banner` | Suppress the startup banner. |
| `reviewer doctor` | Check Python, git, `gh`, login, remote, generated files and secret. |
| `reviewer --version` | Print `reviewer 0.1.0`. |
| `reviewer --help` | Print help. |

Exit codes: `0` success, `1` setup or environment error, `2` command-line usage error.

The banner is plain text only: no colour, no ANSI escapes, no emoji. It is shown only on a TTY unless suppressed by `--no-banner`, `REVIEWER_NO_BANNER` or `NO_COLOR`, and falls back to a one-line form on narrow terminals.

## 6. Generated files

| Path | Contents |
| --- | --- |
| `.github/reviewer/review.py` | Standard-library runner: GitHub API fetch, diff parser, provider calls, review posting. |
| `.github/reviewer/prompt.md` | Review instructions passed to the model. |
| `.github/workflows/pr-review.yml` | `pull_request` workflow with sparse checkout and minimal permissions. |

Each generated file starts with an SPDX identifier and the copyright line. Re-running `reviewer init` rewrites them. Files without the `Generated by reviewer` marker are called out before any overwrite.

The runner skips lockfiles, `.min.*` files, images, archives, fonts, and `dist/`, `build/`, `vendor/`, `node_modules/`; caps the diff at 60000 characters; caps inline comments at 15; and falls back to a body-only review on HTTP 422.

## 7. Providers

| Provider | Default model | Default base URL | Endpoint status |
| --- | --- | --- | --- |
| Gemini | `gemini-2.5-flash` | fixed by runner | Verified |
| Anthropic | `claude-sonnet-5-5` | fixed by runner | Verified |
| OpenAI | asked (required) | `https://api.openai.com/v1` | Verified |
| Ollama | asked (required) | `http://localhost:11434/v1` | Verified |
| OpenCode Zen | asked (required) | `https://opencode.ai/zen/v1` | **UNVERIFIED** |

Verification notes:

- Gemini uses `POST /v1beta/models/{model}:generateContent`. Its upper-case `responseSchema` is spec-locked; the runner keeps a plain-JSON extraction fallback because current docs emphasise `response_json_schema` with lower-case types.
- Anthropic uses `POST /v1/messages` with a forced `submit_review` tool, `x-api-key` and `anthropic-version: 2026-10-21`.
- OpenAI uses Chat Completions JSON mode, retries, and a fallback when a server rejects `response_format`.
- Ollama's OpenAI-compatible base URL and `/chat/completions` are verified. GitHub-hosted runners cannot reach `localhost`: use a self-hosted runner.
- The OpenCode `https://opencode.ai/zen/v1` default could not be confirmed from current docs, which show `https://opencode.ai/inference/openai/v1` for Chat Completions. The spec's default is kept; change it at step 3 if needed.

## 8. Security and privacy

- The API key is read with `getpass` or `AI_REVIEW_API_KEY`, passed to `gh secret set` via stdin, and never written to a generated file, log, traceback or argv. An optional saved copy lives in `~/.config/reviewer/api_key` with mode `600`.
- Only non-secret answers are remembered in `~/.config/reviewer/defaults.json`.
- The workflow uses `contents: read` and `pull-requests: write` only.
- Fork pull requests do not receive secrets, so the runner exits quietly in that case.
- The selected provider receives the pull-request diff and your extra rules. Free tiers may use submitted data for training; check the provider's terms before sending private code.
- The runner redacts the key from its error annotations. It always exits `0` so a review failure cannot block CI.

## 9. Troubleshooting

Run `reviewer doctor` first. Then check:

- **`Resource not accessible by integration`** — the workflow needs `pull-requests: write`; re-run `reviewer init` to regenerate it.
- **`HTTP 429`** — the provider is rate-limiting; retry later or switch model.
- **No review on a PR** — drafts are skipped, and fork PRs get no secrets.
- **`Could not post review (HTTP 422)`** — a comment pointed at an invalid line; the runner folds all comments into the review body.
- **`localhost` unreachable** — Ollama needs a self-hosted runner.
- **`gh` not installed or not logged in** — install it and run `gh auth login`, or set the secret by hand.

## 10. FAQ

**Does it need a third-party Python package?**
No. The CLI and generated runner use only the Python standard library.

**Can I review private repositories?**
Yes, but the diff is sent to the provider you choose. Review the provider's data policy first.

**Does it approve or request changes?**
No. It posts a single `COMMENT` review with findings and fixes.

**What if the model invents a problem?**
The prompt forbids speculation and inline comments use only valid new-side lines from the diff.

**How do I change the provider or model later?**
Re-run `reviewer init`.

## 11. Alternatives

reviewer is a small setup helper, not a replacement for hosted review products.

- **GitHub Copilot code review** — a GitHub-native option; see <https://docs.github.com/en/copilot/concepts/about/copilot-code-review>.
- **CodeRabbit** — a hosted AI reviewer with its own GitHub App; see <https://www.coderabbit.ai/>.
- **Qodo Merge (formerly PR-Agent)** — an open-source AI PR tool with more configuration surface; see <https://github.com/qodo-ai/pr-agent>.

Use whichever fits your security, cost and workflow needs.
